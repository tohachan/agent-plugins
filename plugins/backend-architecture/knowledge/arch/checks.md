# Architecture styles & boundaries — audit checklist

> **Scope:** the macro shape of a system (monolith, modular monolith, microservices, serverless, event-driven), how it is cut (bounded contexts, business capabilities, data ownership), how parts talk (sync vs async, gateway/BFF), the internal structure of one service (layered, hexagonal, clean), coupling, Conway's law, migration (strangler fig) and decision records. **Hands off to:** endpoint and contract design → API; broker semantics, delivery guarantees, event schemas → MSG; sagas, outbox, cross-service consistency → IDEM; timeouts, retries, circuit breakers on inter-service calls → RES; partitioning and horizontal scaling → SCALE; per-service DB schema and migrations → DATA; service-to-service auth → SEC; pipelines and deploy independence mechanics → OPS.

## Audit checklist

| ID | Check | Evidence / search hints | Default severity |
| --- | --- | --- | --- |
| ARCH-CHK-1 | Is the chosen style justified by team size, domain clarity, scaling and ops maturity? | Count deployables (Dockerfiles, `cmd/*` in Go, `apps/*`/`services/*` in monorepos, Helm charts) vs contributors (`git shortlog -sn --since=1.year`); look for an ADR on style. Service/team counts are investigation hints; fail on evidenced ownership/operational overload or documented release contention that the chosen boundaries cause. Verifies ARCH-BP-1, ARCH-AP-4, ARCH-AP-7. | Medium |
| ARCH-CHK-2 | Are boundaries aligned with business capabilities rather than entities or layers? | List services/modules: names like `user-service`, `data-service`, `db-api`, `common-logic` are leads. Read 2–3 user flows: do they cross ≥ 3 services for a single command? Investigate entity/layer-shaped boundaries and coordinated writes; fail only when they demonstrably scatter invariants or obstruct change, with no justified ownership/workflow design. Verifies ARCH-BP-2, ARCH-AP-3. | Medium |
| ARCH-CHK-3 | Does each table have exactly one writing service? | Compare DB connection strings across services (env vars `DATABASE_URL`, Helm values, terraform `*_db_*`); grep SQL/ORM models for the same table names in several repos; check DB grants. Fail: two deployables writing the same table, or reading another's schema. Also check Redis key prefixes and buckets used by more than one service. Verifies ARCH-BP-4, ARCH-BAD-1, ARCH-BAD-16, ARCH-AP-2. | High (Critical if concurrent writers corrupt invariants today) |
| ARCH-CHK-4 | Are module boundaries enforced inside the monolith/service? | Go: imports across `internal/<module>/...` from other modules (`go list -deps`, `depguard`/`go-arch-lint` config); Node: deep imports `../../other-module/src/`, `eslint-plugin-boundaries`, `dependency-cruiser`, Nx `enforce-module-boundaries`. Fail: no rule and cross-module internal imports found. Verifies ARCH-BP-8, ARCH-BAD-2. | Medium |
| ARCH-CHK-5 | Do synchronous paths meet their latency and failure budgets? | Trace end-to-end latency, fan-out and failure behavior; inspect budgets and measurements. Depth >3 is only a lead. Fail only for an evidenced unmet requirement or material failure path. ARCH-BP-6. | By demonstrated impact |
| ARCH-CHK-6 | Does each sync dependency have defined failure behaviour? | For each client found in CHK-5, check timeout/fallback (→ RES) and whether the feature degrades. Fail: a non-essential dependency outage fails the core use case. Verifies ARCH-BP-7. | High |
| ARCH-CHK-7 | Is domain logic separated from transport and persistence? | Read handlers/controllers (`http.HandlerFunc`, `gin.Context`, Express `router.post`, NestJS controllers): SQL, ORM calls and business rules inline are leads; check whether consumers duplicate handler logic. Fail: same rule implemented in ≥ 2 entrypoints or rules untestable without DB. Verifies ARCH-BP-9, ARCH-BAD-5. | Medium |
| ARCH-CHK-8 | Is the abstraction level proportionate? | Count interfaces with a single implementation and no test double use (`type .* interface` in Go; `interface I.*`/abstract classes in TS); count DTO mapping files per entity. Layer/mapping counts are leads; fail only when redundant abstraction creates concrete change/test cost without a requirement. Verifies ARCH-BP-10, ARCH-BAD-6, ARCH-AP-8. | Low |
| ARCH-CHK-9 | Are vendor/legacy models isolated behind adapters? | Grep domain packages for vendor imports: `github.com/stripe/stripe-go`, `aws-sdk-go-v2`, `stripe`, `@aws-sdk/`, legacy client packages. Fail: vendor types in domain/use-case signatures. Verifies ARCH-BP-12, ARCH-BAD-7. | Low |
| ARCH-CHK-10 | Is the gateway/BFF free of domain logic? | Read gateway config (Kong/Envoy/NGINX/APISIX plugins, custom Lua/JS), BFF code: look for pricing, eligibility, state transitions. Fail: business rules in edge components. Verifies ARCH-BP-11, ARCH-BAD-8. | Medium |
| ARCH-CHK-11 | Can each service be deployed alone without coordination? | CI workflows (`.github/workflows/*.yml`): separate pipelines per service? Release notes/runbooks mentioning deploy order; shared domain libs pinned in many `go.mod`/`package.json`. Fail: documented deploy ordering or lockstep version bumps. Verifies ARCH-BP-14, ARCH-BAD-12, ARCH-AP-1. | High |
| ARCH-CHK-12 | Are inter-service contracts explicit and compatibility-checked? | Look for `openapi.yaml`, `*.proto` + `buf.yaml` with `breaking`, AsyncAPI, schema registry config, Pact files. Fail: contracts implicit in code with no breaking-change check in CI. Verifies ARCH-BP-8, ARCH-BP-14. | Medium |
| ARCH-CHK-13 | Is there a shared library carrying domain models across services? | Grep for packages named `common`, `shared`, `models`, `core-lib` imported by multiple services; inspect for entity structs/classes. Fail: domain types shared across contexts. Verifies ARCH-BAD-3, ARCH-AP-1. | Medium |
| ARCH-CHK-14 | Are cross-service transactions avoided (no 2PC, no multi-service writes in one request without saga/outbox)? | Grep `XA`, `PREPARE TRANSACTION`, `dtm`, sequences of writes to multiple services in one handler with no compensation. Fail: multi-service writes without compensation or outbox. Verifies ARCH-BP-5, ARCH-BAD-9 (→ IDEM). | High |
| ARCH-CHK-15 | Are events meaningful domain facts with owned, versioned schemas? | Read event type names and payloads (`*Event` structs, topic names, AsyncAPI). Fail: generic `EntityUpdated`/`Changed`, consumers calling back for every event, no schema ownership. Verifies ARCH-BP-19, ARCH-BAD-10, ARCH-BAD-15. | Medium |
| ARCH-CHK-16 | Are multi-step business processes visible (orchestrated or documented)? | Look for workflow engine (Temporal, Step Functions, Camunda), process managers, or flow docs/event catalogue. Fail: process spanning ≥ 4 services with only implicit choreography. Verifies ARCH-AP-9. | Medium |
| ARCH-CHK-17 | Does ownership map 1:1 from teams to services/contexts? | `CODEOWNERS`, service catalogue (Backstage `catalog-info.yaml`), on-call rotations. Fail: services without an owner, or one service with ≥ 3 owning teams. Verifies ARCH-BP-13, ARCH-BAD-14, ARCH-AP-6. | Medium |
| ARCH-CHK-18 | Does coupling create a demonstrated change or isolation bottleneck? | Use release contention, change-failure history and ownership evidence. Most tables in one deployable is normal for a small monolith; do not flag it without a concrete consequence. ARCH-AP-6. | Medium |
| ARCH-CHK-19 | Is legacy migration incremental (strangler) with a routing facade and an end state? | Gateway/proxy routes splitting legacy vs new, CDC/sync jobs, migration tracker. Fail: parallel rewrite with no traffic moved, or new and legacy both writing the same data without an owner. Verifies ARCH-BP-15, ARCH-BAD-11. | Medium (High if dual ownership of data) |
| ARCH-CHK-20 | Are significant architecture decisions recorded as ADRs? | `docs/adr/`, `adr/`, `architecture/decisions/`, `log4brains`, `adr-tools` files. Fail: none, or style/boundary/data-store choices absent. Verifies ARCH-BP-16, ARCH-BAD-13. | Low |
