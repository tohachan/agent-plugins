# Observability — audit checklist

> **Scope:** the signals that tell you what production is doing and why: structured logs, metrics, distributed traces, profiles, error tracking; SLIs/SLOs and error budgets; alerting, dashboards, runbooks, postmortems; audit vs debug logging. **Hands off to:** health/readiness semantics and degradation → RES; probe and rollout wiring → OPS; PII classification, secret handling and audit-log tamper-proofing → SEC; queue mechanics behind lag signals → MSG; latency budgets and profiling-driven optimisation → PERF; autoscaling on these signals → SCALE.

## Audit checklist

| ID | Check | Evidence / search hints | Default severity |
| --- | --- | --- | --- |
| OBS-CHK-1 | Are logs structured with level, service, version and trace correlation? | Go: grep `log.Printf`, `fmt.Println`, `log.Fatal` vs `slog.`, `zap.`, `zerolog`; Node: `console.log` vs `pino`, `winston`. Confirm the logger emits JSON and includes `trace_id` (look for `otelslog`, pino mixin, `@opentelemetry/instrumentation-pino`). Fail: printf/console logging in request paths or no trace ID. Also check constant messages and log-once-per-error. Verifies OBS-BP-1, OBS-BP-3, OBS-BAD-1, OBS-BAD-3, OBS-BAD-4. | Medium |
| OBS-CHK-2 | Are secrets/PII kept out of logs, spans and error events? | Grep log calls near `password`, `token`, `authorization`, `cookie`, `req.body`, `r.Header`, `%+v` of request structs, `JSON.stringify(req`; check pino `redact`, slog `ReplaceAttr`, Sentry `beforeSend`/`sendDefaultPii`. Fail: any credential or full body logged. Verifies OBS-BP-4, OBS-BAD-2. | High (Critical if credentials/card data confirmed) |
| OBS-CHK-3 | Is log level configurable at runtime and DEBUG off in prod? | Check `LOG_LEVEL` in Helm values/k8s env; grep `LevelDebug`, `level: 'debug'`; look for level endpoint or flag. Fail: prod manifests set debug or level is hard-coded. Verifies OBS-BP-2, OBS-BAD-5. | Low |
| OBS-CHK-4 | Is log volume bounded (sampling, no per-request INFO duplicates, budget)? | Count log calls in hot handlers/loops; look for sampler config (`zap.NewSamplerWithOptions`, custom slog handler), Collector `filter`/`probabilistic_sampler` for logs. Fail: per-iteration logs in loops or per-request logs plus access logs at high RPS. Verifies OBS-BP-5. | Medium |
| OBS-CHK-5 | Does every service expose RED metrics with histograms? | Go: `promauto`, `prometheus.NewHistogramVec`, `otelhttp`, `otelgrpc`; Node: `prom-client`, `Histogram`, `@opentelemetry/sdk-metrics`. Check a `/metrics` route or OTLP metric exporter and scrape config (ServiceMonitor/PodMonitor, annotations). Fail: no duration histogram per route, or only averages/summaries. In dashboards/rules, flag `avg(` applied to per-pod quantile series. Verifies OBS-BP-6, OBS-BP-7, OBS-BAD-7, OBS-BAD-8. | Medium |
| OBS-CHK-6 | Are metric labels bounded and names conventional? | Grep label sets: `WithLabelValues(`, `labels(`, `.add(1, {`; look for `r.URL.Path`, `req.url`, `req.path`, `userId`, `tenantId`, `err.Error()` as label values. Confirm route template use (`r.Pattern` Go 1.23+, chi `RouteContext`, Express `req.route.path`). Grep metric names for `_ms`, camelCase, counters without `_total`. Fail: any unbounded label value (naming issues alone are Low). Verifies OBS-BP-8, OBS-BAD-6, OBS-AP-4. | Medium (High if Prometheus already shows series growth) |
| OBS-CHK-7 | Is OpenTelemetry tracing initialised and wired into server and client middleware? | Go: `go.opentelemetry.io/otel`, `otelhttp.NewHandler`, `otelhttp.NewTransport`, `otelgrpc`, `otelsql`/`otelpgx`; Node: `@opentelemetry/sdk-node`, `auto-instrumentations-node`, loaded via `--require`/`--import` before app code. Fail: no tracer provider, or outbound clients built with plain `http.Client{}`/`fetch` without instrumentation. Verifies OBS-BP-9, OBS-BP-10, OBS-BAD-10. | Medium |
| OBS-CHK-8 | Is trace context propagated through message brokers and jobs? | Grep producers/consumers (`sarama`, `franz-go`, `kafkajs`, `amqp`, `sqs`, `bullmq`) for `propagation`, `Inject(`, `Extract(`, `TextMapCarrier`, header maps. Fail: no injection on publish or consumers start root spans. Verifies OBS-BP-9, OBS-AP-5. | Medium |
| OBS-CHK-9 | Is sampling deliberate (parent-based head and/or tail keeping errors)? | Check `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG`, `sdktrace.ParentBased`, Collector config for `tail_sampling` and `loadbalancing` exporter. Fail: `always_on` at high RPS (cost), or 1% head-only with no error retention. Check exporter batch/queue limits (`sdktrace.WithBatcher`, `BatchSpanProcessor` `maxQueueSize`) and spans created inside loops. Verifies OBS-BP-11, OBS-BAD-13, OBS-BAD-16. | Low |
| OBS-CHK-10 | Are SLIs/SLOs defined for user-facing journeys with an error-budget policy? | Look for `slo*.yaml` (Sloth, Pyrra, OpenSLO), recording rules `*:sli_*`, docs in `docs/slo*`. Fail: no SLO documents or recording rules for critical endpoints. Verifies OBS-BP-12, OBS-AP-6. | Medium |
| OBS-CHK-11 | Do paging alerts use multi-window burn rates and carry runbook links? | Read `PrometheusRule`/`*.rules.yml`/Terraform alert resources: look for burn factors 14.4/6/1 and paired windows, `runbook_url` annotations, `severity` labels. Fail: pages on CPU/memory/pod restarts, single-window error thresholds, or alerts without runbook. Check also a watchdog/`absent()` rule exists. Verifies OBS-BP-13, OBS-BAD-11, OBS-BAD-15, OBS-AP-2, OBS-AP-9. | Medium |
| OBS-CHK-12 | Are queue lag/age, DLQ depth and worker saturation monitored and alerted? | Check exporters (kafka-exporter, Burrow, CloudWatch SQS metrics), alert rules on `kafka_consumergroup_lag`, `ApproximateAgeOfOldestMessage`, DLQ queue depth; worker in-flight gauges. Fail: async system without lag/age alerts or DLQ without alert. Verifies OBS-BP-14. | High (silent backlog under realistic failure) |
| OBS-CHK-13 | Are pool saturation signals exported (DB pool waits, event-loop delay, goroutines)? | Go: `db.Stats()` export (`WaitCount`, `WaitDuration`), `pgxpool.Stat`, `collectors.NewDBStatsCollector`; Node: `collectDefaultMetrics` (event loop lag), `monitorEventLoopDelay`, pool `waitingCount`. Fail: none exported. Verifies OBS-BP-6. | Medium |
| OBS-CHK-14 | Are key business outcomes measured and alerted on anomalies? | Grep for counters named after domain events (`orders_`, `payments_`, `signups_`). Fail: only technical metrics for a revenue-path service. Verifies OBS-BP-15. | Medium |
| OBS-CHK-15 | Are audit events separated from debug logs and retained per policy? | Look for an audit logger/table/topic (`audit`, `AuditEvent`) and its sink, retention and access config. Fail: security-relevant actions only in sampled app logs or none recorded. Verifies OBS-BP-16. | High for regulated or multi-tenant systems, else Medium |
| OBS-CHK-16 | Are errors reported to an error tracker with release and trace context? | Go: `sentry-go`, OTel exception events; Node: `@sentry/node`, source maps upload in CI, `release` set to git SHA; global `unhandledRejection`/`uncaughtException` handlers. Fail: no tracker or no release tagging. Verifies OBS-BP-20, OBS-BAD-12. | Low |
| OBS-CHK-17 | Does each service have a dashboard as code and runbooks linked from alerts? | Look for `dashboards/`, Grafana JSON, Jsonnet/grafonnet, Terraform `grafana_dashboard`; `runbooks/` or wiki links in alert annotations. Fail: none in repo and no link in alerts. Verifies OBS-BP-17, OBS-BP-18, OBS-AP-3. | Low |
| OBS-CHK-18 | Is continuous profiling available, with debug endpoints not public? | Grep `net/http/pprof` import and which mux/port serves it; `pyroscope`, `parca`, `@pyroscope/nodejs`, `--inspect` in Dockerfile CMD. Fail: pprof on the public server or `--inspect=0.0.0.0`. Verifies OBS-BP-19, OBS-BAD-14. | Medium (High if reachable from the internet) |
| OBS-CHK-19 | Are incidents followed by blameless postmortems with tracked actions? | Look for `postmortems/`, incident templates, linked tickets; ask for last 3 SEV1/2 write-ups. Fail: none, or action items without owners. Verifies OBS-BP-18, OBS-AP-8. | Low |
| OBS-CHK-20 | Can every telemetry signal be tied to a deployed version, and are probe routes excluded from SLIs/logs? | Grep `build_info`, `service.version`, `OTEL_RESOURCE_ATTRIBUTES`, `-ldflags "-X main.version`; check access-log middleware skips `/healthz`, `/readyz`, `/metrics`. Fail: no version on metrics/traces, or probes counted in SLI counters. Verifies OBS-BP-3, OBS-BAD-9. | Low |
