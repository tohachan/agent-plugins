# Security — key decisions

> **Scope:** protecting the API, its data and its runtime: the OWASP API Security Top 10 (2023) as concrete checks, authentication and token handling, authorization models and tenant isolation, input handling and injection, password storage, secrets, transport security, browser-facing controls (CORS, CSRF, headers), security logging and audit trails, supply chain, container and cloud least privilege, data protection. **Hands off to:** rate-limit algorithms, timeouts, load shedding → RES · per-tenant quotas and isolation by cells → SCALE · response shape, versioning, error format, pagination contract → API · log pipeline, alerting, retention tooling → OBS · CI/CD pipeline, config delivery, image build/deploy mechanics → OPS · webhook replay/dedup semantics → IDEM · DB roles and schema details → DATA.

## Key decisions

| Decision | Options | Choose … when | Trade-off |
| --- | --- | --- | --- |
| Identity provider | build in-house / managed IdP (Auth0, Okta, Cognito, Entra ID, Clerk) / self-hosted OIDC (Keycloak, Zitadel, Ory) | Managed or self-hosted OIDC by default; in-house only for a thin wrapper around a vetted library when requirements are trivial | Building yourself means owning MFA, recovery, passkeys, brute-force defence and every CVE; buying means vendor lock-in and per-MAU cost |
| Browser session mechanism | server-side session (opaque ID in cookie) / JWT in HttpOnly cookie / BFF holding tokens server-side / tokens in JS storage | Server-side session or BFF for first-party web apps; bearer JWT for mobile, CLI and service clients; never tokens in `localStorage` for sensitive apps | Sessions need a shared store and give instant revocation; JWTs avoid a lookup but cannot be revoked before expiry without a denylist |
| Token lifetimes | access 5–15 min + rotating refresh (days, absolute cap) / long-lived access / sender-constrained (DPoP, mTLS-bound) | Short access + rotation by default; sender-constrained for high-value APIs (finance, health, admin) | Shorter lifetimes mean more refresh traffic and IdP dependency; sender-constrained tokens add client complexity |
| Authorization model | RBAC / ABAC (attributes, conditions) / ReBAC (relationships, Zanzibar-style) | RBAC for coarse function access; ABAC for rules on attributes (region, amount, time); ReBAC for sharing, hierarchies, per-object grants (docs, folders, orgs) | RBAC explodes into role-per-case for object rules; ABAC/ReBAC need a policy engine and data sync |
| Policy location | in-code checks per handler / shared library + policy-as-code (OPA/Rego, Cedar, Casbin) / external decision service (OpenFGA, SpiceDB, Permit, AWS Verified Permissions) | Shared library once >1 service or >a handful of rules; external service for ReBAC at scale or cross-service consistency | External PDP adds a network hop and a dependency (cache decisions, define fail-closed) |
| Tenant isolation | shared tables + tenant_id (app-enforced) / shared + Postgres RLS / schema per tenant / DB or account per tenant | Shared + RLS as default for SaaS; schema/DB per tenant for regulated or contractual isolation, per-tenant keys, or noisy whales | Stronger isolation multiplies migrations, connections and cost (SCALE) |
| Service-to-service auth | network trust only / mTLS via mesh (SPIFFE IDs) / OAuth2 client-credentials JWT / both | mTLS for workload identity and encryption; add signed tokens when the callee must know the end user or caller scopes | Mesh adds ops weight; tokens alone leave traffic unauthenticated at the transport layer |
| Secrets delivery | env vars from CI / secret manager injected at deploy (External Secrets, CSI driver) / app fetches at runtime / workload identity (no static secret) | Workload identity (IRSA/EKS Pod Identity, GKE/Azure WI) for cloud APIs; secret manager for the rest; rotate automatically | Env vars leak via crash dumps, `/proc`, child processes; runtime fetch adds a startup dependency |
| Data-at-rest protection | disk/volume encryption only / + field-level (application) encryption / + tokenisation | Field-level envelope encryption (KMS) for high-risk fields (government IDs, health, bank data, secrets you store for users); tokenisation for card data (PCI scope reduction) | Field encryption breaks querying/indexing (use blind indexes), adds key management and latency |
