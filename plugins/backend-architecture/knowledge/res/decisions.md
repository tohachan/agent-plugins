# Resilience — key decisions

> **Scope:** keeping a service up and correct when its dependencies, its own instances or a whole failure domain misbehave: timeouts and deadlines, retries, circuit breakers, bulkheads, load shedding, rate limiting, backpressure, degradation, health checks, draining, redundancy, dependency SLAs, failure testing, and recovery dynamics (thundering herds, hedging, metastable failures). **Hands off to:** making retried writes safe → IDEM; worker shutdown, cancellation plumbing and bounded fan-out → CONC; broker redelivery and DLQs → MSG; capacity planning and autoscaling → SCALE; cache stampede protection → CACHE; SLOs, alerts and dashboards → OBS; abuse-oriented rate limiting and auth → SEC; deploy strategy and rollbacks → OPS; error/status contracts → API.

## Key decisions

| Decision | Options | Choose … when | Trade-off | Rules |
| --- | --- | --- | --- | --- |
| Where resilience policy lives | in-app libraries / service mesh or proxy (Envoy, Istio, Linkerd) / both, split by concern | Mesh for uniform outbound timeouts, retry budgets, outlier ejection across many services; in-app for semantics the proxy cannot see (idempotency, fallbacks, per-operation deadlines); avoid configuring retries in both | Mesh centralises but is blind to business semantics; in-app is precise but drifts across services and languages | RES-BP-6, RES-BP-7, RES-BP-5 |
| Which layer retries | edge client only / the layer closest to the failing dependency / every layer | Retry at exactly one layer — usually the one directly calling the dependency; edge clients only for idempotent calls with keys | Single-layer retry limits amplification; edge retry gives users resilience but multiplies load if inner layers retry too | RES-BP-6, RES-BP-3, RES-AP-1, RES-BAD-4 |
| Failure isolation for a dependency | none / timeout + retry / circuit breaker / bulkhead (separate pool or concurrency limit) / async via queue | Breaker + bulkhead for any dependency that can be slow (not just down) and serves non-critical features; queue when the caller does not need the result synchronously | Breakers need tuning and can flap; bulkheads strand capacity; queues make the flow eventually consistent (IDEM) | RES-BP-7, RES-BP-8, RES-BAD-10, RES-BAD-11 |
| Overload response | queue everything / static concurrency limit / adaptive concurrency limit (AIMD, gradient) / priority-based shedding | Static limit as baseline; adaptive when load and latency vary widely; priorities when traffic classes differ in value (checkout vs recommendations) | Queues hide overload until timeouts; static limits drift as code changes; adaptive limits add tuning | RES-BP-9, RES-BP-11, RES-BAD-9, RES-AP-5, RES-AP-7 |
| Rate-limit algorithm and scope | token bucket / GCRA / sliding-window counter / fixed window; per instance / global (Redis) / at gateway | Token bucket or GCRA for bursts with a sustained rate; sliding window for quota-style limits; gateway/global when clients spread over many instances; per-instance as cheap first line | Global needs a fast shared store and fails open/closed; per-instance limits drift with replica count; fixed windows allow 2× bursts at edges | RES-BP-10, RES-BAD-12 |
| What happens when a dependency is down | fail the request / static or cached fallback / degrade feature / queue for later | Fail for writes that must be correct (payment); stale cache for reads that tolerate staleness; degrade for optional features; queue for writes that can be deferred | Fallbacks are code paths rarely exercised — they rot unless tested | RES-BP-12, RES-BAD-13, RES-AP-6 |
| Redundancy level | single AZ / multi-AZ / multi-region active-passive / active-active | Choose single/multi-AZ from accepted outage and budget (RES-BP-15; three zones are not mandatory); multi-region when RTO/RPO or placement requires surviving region loss | Each level roughly doubles cost and adds consistency problems (IDEM, SCALE) | RES-BP-15, RES-BP-16, RES-BAD-14, RES-AP-9 |
| Health signal semantics | liveness only / liveness + readiness / + startup probe | All three for slow-starting services (JVM, large caches, migrations); liveness + readiness otherwise | Mis-scoped probes cause restart loops and fleet-wide unreadiness | RES-BP-13, RES-BAD-5, RES-BAD-6, RES-AP-3 |
