# Behavioral evaluation protocol

These cases test detection, restraint, repair correctness and evidence calibration. Do not load eval prompts/graders during ordinary skill use.

Run each case in a fresh disposable workspace. Scaffold scripts copy fixtures there; do not run them in a production repository. The shared orders-service fixture lives under `skills/backend-audit/evals/_fixtures/`; case directories refer to it rather than maintaining divergent copies.

Use the installed Claude plugin eval runner (see `claude plugin eval --help` for that version). The existing per-skill `evals/<case>/{case.yaml,prompt.md,graders/}` contract is retained. Capture final report artifacts as well as traces; a report saved to disk is not absent merely because chat has a short summary. Run `python3 scripts/validate_report.py <report> --evidence-root <workspace>` separately; LLM format graders are supplementary, not arithmetic/schema validators.

For a meaningful comparison use the same model/version, limits, tools, fixture and user prompt with (A) no backend skill, (B) previous plugin and (C) revised plugin. Keep evaluator rubric identical and blind to condition. Use separate contexts and at least three runs per condition; record input/output/cached tokens, elapsed time and errors, not just a pass/fail average. Confirm traces actually loaded the intended skill. Do not include graders or expected answers in the task context.

Measure per-case supported defect recall, unsupported/false findings, minimal-fix correctness, treatment of unknowns and preserved guarantees. Healthy cases specifically penalize invented High/Critical findings. Aggregate separately by audit/design, scope and healthy/defective/incomplete context. Report raw counts, run variability and token cost per supported useful finding; a single composite score hides trade-offs. Count incomplete/failed runs rather than silently dropping them.

The healthy-boundaries / split-dedup-transaction pair changes the transaction boundary and schema while preserving a valid inherited HTTP deadline. Incomplete-evidence withholds the schema. Gateway-owned-auth traces a Node.js control through gateway configuration and deployment. Partition-commit-gap tests a plausible but unsafe fix. Domain-invariant-coverage tests coverage discipline in a neutral domain: a guard present in one writer and missing in others, an obligation whose purge predicate real data never reaches, a stranded workflow state, and a complete coverage inventory derived from the registry and the target's own policy document. Design cases cover provider limitations, constrained deployment and ordered deltas. Backend-rules idempotency-lookup checks that a single-area lookup finds the defect without producing a report or loading other areas. Orders-service-full-audit runs without the Agent tool and so exercises the sequential full-audit path; add a variant with `Agent` in `allowed_tools` to exercise the reviewer/verifier path, and compare both on recall and tokens. Keep additional real-project holdouts separate from tuning cases; expand Node.js and multi-service production coverage before claiming broad stack effectiveness.

No baseline or improvement percentages are claimed by this repository. Record actual run results outside the skill-loading path with model/plugin versions and fixture hashes. Local deterministic checks validate the harness and report contract, not model effectiveness.
